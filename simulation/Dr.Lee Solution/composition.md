# DFlash + Suffix Extension — 최종 보고

> **한 줄 주제**: 신규↔반복을 오가는 LLM 서빙에서 **DFlash + Suffix는 처리량 우월한 추측기 "쌍"**이며,
> 둘을 **적응적으로 묶은 Extension**이 모든 단독·대안을 이긴다.
>
> **읽는 순서**: ① 왜 이 쌍인가 → ② 왜 이론적으로 더 나은가 → ③ 어떻게 만드나 → ④ 결과.
> 각 슬라이드는 굵은 한 줄(핵심 메시지)로 시작. 그림은 `experiments/extension_dflash_suffix/*.png`.

---

## 슬라이드 1 — 주제 한 장 (thesis)

**DFlash + Suffix는 보완적이고 둘 다 싼 추측기 쌍이고, 적응적으로 묶으면 어느 단독·대안보다 빠르다.**

- **① 올바른 쌍**: DFlash(예측·구조적) ⟂ Suffix(기억·반복) — 직교 보완 + **둘 다 O(1)**(블록 1-forward / CPU).
- **② 적응이 단독을 이김**: vs DFlash **+73~101%**, vs Suffix(cold 압승·warm 동률 → 상한선), 닫힌형 제어로
  oracle을 **93%(label) → ~99~100%(라이브)** 추종.
- **③ 대안·선행 초과**: 모델끼리 Fusion **−20%**, 논문 스위치 대비 cold **1.25×**·템플릿 **2.03×**, tree **+21~82%**.

> **정직한 범위**: 이득의 원천은 **보완 쌍 + 적응 + 싼 fallback**이다. "둘을 한 draft에 섞는 합성 자체의
> 시너지(bridge)"는 동일-반복 워크로드선 **0**이고, **템플릿형(변수 슬롯)에서만 2.03×**로 실재한다(슬 24).

## 슬라이드 2 — 기호 정의 (notation, 한 번에)

**"신뢰도"는 전부 hazard $a_k$를 가리킨다.**

| 기호 | 뜻 | 성질 |
|---|---|---|
| $a_k$ | **신뢰도 = hazard** = 위치 $k$ **조건부 채택률**: "앞 $k{-}1$개 다 맞힌 전제 하 $k$번째 맞을 확률" | 한 칸·조건부 → **비단조 가능** |
| $S_k$ | **생존**: "앞 $k$개 **전부** 맞힐 확률" $=a_1a_2\cdots a_k$ | 누적 → **항상 감소** |
| $G_k$ | 머리가 번 기대 토큰 $=S_1+\cdots+S_k$ | |
| $T$ | **warmth(꼬리 가치)**: 꼬리 발동 시 평균 채택 길이 | 이력 의존 → 온라인 추정 |
| $\rho$ | 꼬리 **게이트** $=S_k$ | 자유변수 아님(측정값) |
| $K,\ \tau,\ R$ | 한 라운드 채택 $K{=}1{+}G_k{+}S_kT$ / 시간 $\tau$ / 처리량 $R{=}K/\tau$ | |
| $a^*,\ k^*$ | 임계값 $T/(1{+}T)$ / 최적 머리 길이($k^*{=}k_{df}$) | $a_k>a^*$ 동안 머리 추측 |
| $\hat\pi$, oracle | 우리 온라인 정책($a_k,T$ 추정) / 참값 알고 최적 $k$ 고르는 천장 | $R^{*}_{\text{단독}}\le R(\hat\pi)\le R_{\text{oracle}}$ |

> **핵심 한 쌍**: hazard $a_k$(한 칸, 비단조) ↔ 생존 $S_k$(누적, 감소), $S_k=a_1\cdots a_k$.
> (위치는 $i$, 고른 머리 길이는 $k$로 표기 — 같은 양, 평가 지점만 다름.)

## 슬라이드 3 — 출발점: 추측기마다 잘하는 게 다르다

**Speculative decoding = 싼 추측기가 미리 찍고 target이 한 번에 검증. 후보가 여럿이고, 워크로드마다
누가 잘 찍는지 다르다.** (DGX Spark GB10 + Qwen3.5-27B, SpecBench 6 task)

| 추측기 | 어떻게 | 비용 | 최고 |
|---|---|---|---|
| **DFlash** | 작은 모델이 블록을 **병렬 한 번에** | **O(1)** | 구조적 **3.14×** |
| MTP | target 1-layer가 한 토큰씩 | O(k) | 구조적 2.45× |
| **Suffix** | 과거 텍스트를 **기억**해 이어붙임 | ~0 (CPU) | 반복 시 **7~8×** |

> (작은 모델 단독 draft는 Qwen3.5에선 vLLM이 MTP로 강제 변환해 분리 측정 불가 — MTP가 그 역할.)

## 슬라이드 4 — 핵심 발견: 강점이 직교하는 두 축으로 갈린다

**예측을 잘함 vs 기억을 잘함 — 두 직교 축. 어느 하나로는 모든 워크로드를 못 잡는다.**

| 워크로드 | 누가 | 왜 |
|---|---|---|
| 수식·번역·요약 (**규칙적**) | **DFlash/MTP** | 다음 토큰이 뻔해 모델이 잘 찍음 |
| 같은/비슷한 요청 **반복** | **데워진 Suffix** | 과거 답을 외워 깊이 맞춤 |
| 열린 질문·대화 (**자유**) | 아무도 못함 | 다음 토큰 본질적 예측 불가 |


> 그림 = **hazard $a_k$**(한 칸·조건부). math는 깊이까지 ~0.9(구조적), qa는 ~0.55(자유형). $a_k$는
> 조건부라 **비단조 가능**(math가 5번째서 꺼졌다 회복). **생존 $S_k$**(누적·감소)와 다름: $S_k=a_1\cdots a_k$.

---

## 슬라이드 5 — $a_k$ 모양은 model proposer끼리 공유 (프레임워크 일반성)

**`a_k`의 task별 모양은 텍스트 예측가능성이라 DFlash·MTP·EAGLE-3가 공유한다 — DFlash 특수가 아니다.**

- **모양 동일**: 둘 다 math>rag>summ>qa → 슬 4 메시지 일반화.
- **깊이 차이**: MTP(AR)는 자기 앞에 조건화 → 깊이서 **평평**(qa 0.69→0.68). DFlash(non-AR, [MASK] 독립
  예측)는 자유형서 **빨리 꺼짐**(qa 0.68→0.48). EAGLE-3(미측정)는 MTP 모양인데 더 높음.
- **함의**: 임계값·트리 수식이 셋 다에 적용. 그래도 **DFlash를 쓰는 이유 = O(1) draft 비용**(MTP/EAGLE O(k)).

---

## 슬라이드 6 — 어떻게 합치나? 조합 오라클이 답

**설계 시점에 모든 조합 속도를 측정값으로 계산해 보니, 모델끼리 묶는 건 손해였고 "DFlash 머리 +
Suffix 꼬리"로 이어 붙이는 것만 이득이었다.**

- **모델끼리 병렬(Fusion)** → 구조적 task **−20%** (강점 겹쳐 이득 적은데 비용만↑).
- **DFlash → Suffix 직렬(Extension)** → best-single 이기고 **반복될수록 더 좋아짐**.

> 직관: 강점이 정반대(예측 vs 기억)라 **겹치지 않고 보완** → 묶기보다 **이어 붙이기**.
> ⚠ 여기 "조합 오라클"(설계용, 만들 조합 선택) ≠ 슬 11의 "결정 오라클"(런타임 머리 길이 선택).

## 슬라이드 7 — 왜 "머리+꼬리"가 자연스러운가

**DFlash는 앞쪽을 정확히, 데워진 Suffix는 뒤쪽을 깊이 — 위치로 역할이 나뉜다.**

> 그림 = **생존 $S_i$**(누적, 항상 감소). (슬 4의 한 칸 hazard와 다름.)

- 파랑(DFlash): 앞 1~2 토큰 가장 정확, 깊으면 감소.
- 주황(Suffix·warm): 깊이까지 유지 → 앞 1~2 지나면 DFlash 추월. 회색(cold): ≈0.
- → **DFlash가 짧게 운 떼고(primer), warm Suffix가 길게 잇는다(tail).**

---

## 슬라이드 8 — 왜 '스위치'가 아니라 '합성'인가 (모티베이션)

**agentic·템플릿형 응답엔 한 줄에 두 토큰이 섞인다 — 변수(둘 다 못 맞춤)와 본문(Suffix가 외움).
각 단독도, 스위치도 반쪽만 한다.**

```
"고객 [이름]님, 주문 [번호]는 [날짜] 배송됩니다.  자세한 내용은 마이페이지에서..."
        └변수┘     └변수┘   └변수┘   └────────── 고정 본문(매번 동일) ──────────┘
```

| | 변수 | 본문 |
|---|---|---|
| Suffix | ✗ 변수가 매칭 끊음(`m_raw=0`) | ✓ 외워서 길게 |
| DFlash | ✗ 랜덤 | △ 예측되나 블록(O(1)) 짧게만 |

- **문제**: 변수가 Suffix 본문 진입을 끊고, DFlash는 본문을 짧게만 → 누구도(스위치도) "변수 통과 + 본문
  길게"를 한 라운드에 못 함.
- **합성의 해법(bridge)**: DFlash 머리가 변수 건너 본문으로 **다리** → Suffix 재동기화 → 한 draft에 통째.

> 그래서 스위치(둘 중 하나)가 아니라 **합성**(둘을 직렬). 정량은 슬 24(템플릿 2.03×). 동일-반복엔 변수가
> 없어 이 이득은 안 생김 — **문제가 있어야 해법이 값을 가짐.**

## 슬라이드 9 — 속도를 수식으로

**"한 라운드 채택 토큰 ÷ 시간"이 속도. 머리·꼬리를 넣으면:**

$$R=\frac{K}{\tau},\qquad K=\underbrace{1}_{\text{보너스}}+\underbrace{G_k}_{\text{머리}}+\underbrace{S_k\,T}_{\text{꼬리}}$$

**각 항의 함수 형태** (머리 hazard $a_i$, 꼬리 hazard $b_j$로부터):
$$S_k=\prod_{i\le k}a_i,\qquad G_k=\sum_{i=1}^{k}S_i=\sum_{i=1}^{k}\prod_{j=1}^{i}a_j,\qquad T=\sum_{m\le M}\prod_{j\le m}b_j$$
$$\big(\,G_k = a_1 + a_1a_2 + a_1a_2a_3 + \cdots + a_1a_2\cdots a_k\,\big)$$

**왜 이 꼴인가** (검증기는 첫 틀린 곳에서 멈춤 → 채택은 prefix만):
- **$S_k=\prod a_i$ (누적곱)**: "$k$개 **전부** 맞을 확률" = 매 칸 조건부 $a_i$를 다 곱함. 각 $a_i<1$ → **항상 감소**.
  - **$S_i$의 두 가지 읽기 (같은 숫자)**: ① **확률** "앞 $i$개 다 맞을 확률" ② **기여** "토큰 $i$가 평균 통과되는 정도(0~1)".
    같은 이유: 토큰 $i$ 통과 ⟺ 앞 $i$개 다 맞음. → **0/1의 평균 = 1일 확률**이라, 토큰마다 더하면(확률 합) **기대 개수** $G_k$(1 넘을 수 있음). (= survival: "$i$째까지 안 틀리고 살아남을 확률".)
  - **실제론 곱 안 하고 직접 측정**: $S_i = P(\text{matched length}\ge i) = \dfrac{\#\{\text{라운드}: j\ge i\}}{\#\text{전체}}$,
    즉 "**DFlash가 $i$개 이상 맞힌 라운드 비율**". (예: $j$=[3,1,5,0,2,…] → $S_1{=}P(j{\ge}1)$, $S_2{=}P(j{\ge}2)$…)
    캡처의 matched length $j$ 분포에서 바로 나옴(`_SDF`). $a_i=S_i/S_{i-1}$는 역산. → **$\mathbb{E}[N]=\sum_i P(j\ge i)=\sum_i S_i=G_k$** (tail-sum).
- **$G_k=\sum S_i$ (누적합) = 기대 채택 수** $\mathbb{E}[N]$. 채택 토큰 수 $N$에 대해, $i$번째 토큰 채택
  지시함수 $X_i$는 "앞 $i$개 전부 맞음"이라 $\mathbb{E}[X_i]=S_i$ → 선형성으로 $\mathbb{E}[N]=\sum_i\mathbb{E}[X_i]=\sum_i S_i$.
  - **분포로 검산** ($P(N{=}j)=S_j(1{-}a_{j+1})$, $P(N{=}k)=S_k$). $k{=}3$, $a$=.715,.671,.640 ($S$=.715,.480,.307):

    | $N$ | 0 | 1 | 2 | 3 | $\mathbb{E}[N]$ |
    |---|---|---|---|---|---|
    | $P$ | .285 | .235 | .173 | .307 | $0(.285)+1(.235)+2(.173)+3(.307)$ |
    |  | $1{-}a_1$ | $S_1(1{-}a_2)$ | $S_2(1{-}a_3)$ | $S_3$ | $=1.502=G_3$ ✓ |
- → 머리는 **survival 합**(부분점수: 맞은 prefix는 남음), 꼬리 게이트는 **survival 한 점** $S_k$(전부 맞아야 발동). 코드는 $S_k$를 직접 측정하고 $a_k=S_k/S_{k-1}$로 역산.

- $\tau$ = (머리 추측) + (꼬리 추측, 거의 0) + (검증). 보너스 1 = 다 틀려도 나오는 1토큰.
- $T$도 머리와 **똑같은 꼴**(꼬리 생존 합). warm = $b_j$ 큼 → $T$ 큼. → **정할 변수 = 머리 길이 $k$.**

## 슬라이드 10 — 통찰: 꼬리는 "머리가 다 맞을 때만" 작동

**검증기는 첫 틀린 곳에서 멈추므로, 꼬리는 머리 블록이 전부 맞아야 살아남는다. 그래서 $S_k$(머리
생존)가 곧 꼬리 발동 확률 — 자유변수가 아니라 측정값.**

- 머리 한 단어라도 틀리면 → 뒤의 꼬리 통째로 버려짐.
- 꼬리 기여 = (머리 다 맞을 확률 $S_k$) × (꼬리 가치 $T$).
- $S_k$는 DFlash 측정에서 바로 읽음 → **식에 남는 유일한 미지수는 $T$ 하나** (+ 머리 신뢰도 $a_k$).

---

## 슬라이드 11 — [증명 ①] 단독 ≤ 우리 ≤ oracle (바운드)

**꼬리 길이 0으로 두면 Extension = DFlash 단독. 즉 단독은 Extension의 특수경우 → 우리 정책은 단독보다
나쁠 수 없다. 위로는 oracle이 천장.**

> **oracle(결정 오라클)**: 매 라운드 그 문맥의 **참 $(a_k, T)$를 안다고 가정**하고 처리량 최대 머리 길이를
> 고르는 가상 정책. **같은 기계**(DFlash+Suffix+$k$ 선택), 추정 오차 0. *더 좋은 추측기 ✗ · 미래 보기 ✗.*
> 우리와의 격차 = "온라인 학습해야 함"의 비용. (≠ 슬 6 조합 오라클.)

$$\underbrace{\max_k\frac{1+G_k}{\tau}}_{R^{*}_{\text{단독}}\,(\text{꼬리항 없음})}\ \le\ R(\hat\pi)\ \le\ \underbrace{\max_k\frac{1+G_k+S_k\,T(\text{이력})}{\tau}}_{R_{\text{oracle}}\,(\text{꼬리항 있음})}$$

- **상한은 suffix 이력의 함수**: $R_{\text{oracle}}$은 이력으로 데워지며 오르는 **움직이는 표적**(cold $T{\approx}0.5$
  → warm $T{\approx}9.8$), 하한 $R^{*}_{\text{단독}}$은 suffix 무관(고정). 벌어진 간격 = suffix가 이력으로 만든 공간.
- **limit**: cold $T{\to}0$ → 폭 0(단독=oracle). warm $T{\to}\infty$ → 상한 ∝ $T$ 발산, 폭 최대(적응 가치 최대).
- 고정 정책은 한쪽 regime에서 무너지고, **적응 정책만 cold·warm 양쪽에서 상한에 붙는다.**
- **상한에 붙는 정도는 regime 의존** (측정, 슬22): 극단(cold·정확warm, $k^*$가 0/full로 명확)에선 argmax가
  **~99~100%**. **부분-warm·흩어진 슬롯**(composition 핵심)에선 최적 $k$가 라운드마다 갈려 단일추측 chain이
  oracle의 **71~92%**뿐(흩어질수록 갭↑) — 나머지는 **tree가 게이트 제거로** 메움(슬23).
- ⚠ 위 $R_{\text{oracle}}$은 **linear(단일 머리+꼬리, 게이트 $S_kT$ 있음)** oracle. tree는 게이트를 없애
  ($S_kT\to T$) **더 높은 천장**(슬23). (≠ 슬6 조합 오라클.)

## 슬라이드 12 — 오라클에 다가가는 법: 각 항을 어떻게 추정·구현하나 (+ 개선)

**상한에 붙으려면 식 $R=(1+G_k+S_kT)/\tau$ 의 각 항을 실시간 추정·구현해야 한다. 전부 있는 부품이고
항마다 실측 개선이 붙는다.**

| 식의 항 | 정체 | 우리 구현 | 실측 개선 | 상세 |
|---|---|---|---|---|
| 머리 $a_k,S_k$ | 미지수 | DFlash(O(1)) + **confidence로 $a_k$ 라이브** | r=0.99, **warming 0** | 슬13·18 |
| 꼬리가치 $T$ | 미지수(이력) | Suffix(CPU) + **score로 $T$ 라이브** | label보다 **3.7× 빠름** | 슬17 |
| 게이트 $\rho{=}S_k$ | 구조적 | **tree로 제거**: $\boxed{S_kT}\to\boxed{T}$ | **+21~82%** | 슬23 |
| 머리 길이 $k^*$ | 결정 변수 | $k^*=\arg\max_k\,[\,1+G_k+S_kT\,]$ | label **93%** → 라이브 **~99–100%** | 슬13·22 |
| 비용 $\tau$ | 비용 모델 | 실측 검증 | R²≈0.99 | 슬19 |

**두 층위로 작동 — ①②는 "천장에 닿고", ③은 "천장을 올린다":**
- **①추정 + ②결정 = 컨트롤러(한 쌍)** → 주어진 구조의 oracle에 도달(라이브 ~99~100%). ①이 $(a_k,T)$를
  주고 ②(임계값 $k^*$)가 최적 길이를 고름 — 더하기가 아니라 한 묶음.
- **③구조(tree)** = linear-oracle → tree-oracle로 **천장 자체를 +21~82% 위로** 민다 → 그 새 천장에 다시 ①②로 도달.

> 누적: DFlash 단독 $\xrightarrow{\text{①② 슬20}}$ **+73~101%**(linear) $\xrightarrow{\text{③ 슬23}}$ **추가 +21~82%**.
> "추정 100%"는 **linear oracle 기준**이고, tree는 더 높은 oracle로 천장을 올린 것.

**②결정 — 머리 길이 $k^*$를 정하는 세 방법** (warmth $T$를 ctx-only probe로 추정한 뒤):

| 방법 | 규칙 | 특징 |
|---|---|---|
| first-crossing | hazard $a_k>a^*{=}\frac{T}{1+T}$ 인 동안 머리 연장 | 토큰별 한계분석(슬13). ⚠ $a_k$ **비단조**($k{=}3$ 국소 dip)면 **너무 일찍 멈춤** |
| **argmax** ✅ | $k^*=\arg\max_k\,[\,1+G_k+S_kT\,]$ | **단조 survival $S_k$로 K 직접 최대화** → hazard dip 함정 회피. 가장 robust |
| threshold | $T$ 큼(warm)→$k{=}0$(순수 꼬리) / $T{\approx}0$(cold)→full DFlash | 단순 이진 게이트 |

## 슬라이드 13b — 머리 길이 규칙: argmax (전체 가치 $K(k)$ 직접 최대화)

**임계값(슬13)은 hazard가 단조 감소일 때만 argmax와 같다. 실제 DFlash hazard는 비단조(dip)라
first-crossing은 일찍 멈춘다 → $K(k)$를 직접 최대화하는 argmax가 강건. 배포 규칙은 argmax.**

$$k^* = \arg\max_k\, K(k),\qquad K(k)=1+\underbrace{G_k}_{\text{머리}=\sum_{i\le k}S_i}+\underbrace{S_k}_{\text{게이트}}\!\cdot T$$

- **분해(왜 최적점이 생기나)**: 머리 $G_k$=survival 합 → **부분점수**(맞은 prefix는 남음)라 안전하게 누적·포화.
  꼬리 $S_kT$=게이트(머리 **전부** 맞아야 발동)라 $k$↑면 **급락**. 둘의 합 $K(k)$가 한 점에서 peak → 그게 $k^*$.
- **warmth $T$로 peak 이동**: warm($T$ 큼)→$k^*{=}0$(순수 꼬리) / cold($T{\approx}0$)→full DFlash / 부분-warm→중간.
- **왜 first-crossing보다 강건**: hazard $a_k$ 비단조($k{=}3$ dip)면 first-crossing이 dip에서 멈춰 $k{=}2$,
  하지만 $a_4$ 회복으로 $K(k)$는 계속 올라 **argmax $k{=}10$**(라이브 검증, $T{=}2$). **단조 $S_k$로 직접 최대화 → dip 함정 회피.**
- **추정·게이트**: $T$는 ctx-only probe로(머리 앵커 오염 방지), `match_len<10`(cold)이면 곧장 full DFlash.
- **우리 DFlash는 hazard 높고 평평**($a_k{\sim}0.6{-}0.8$) → 머리 늘리기 싸서 $k^*$가 **극단(0/full)**; 중간 $k^*$는
  hazard가 **빨리 감소**하는 모델에서(그림 D), 우리 모델에선 "중간"이 **워크로드 평균**으로 나타남.


> A: 측정 입력(survival $S_k$ + hazard $a_k$) · B: 분해(머리 $G_k$ + 게이트꼬리 $S_kT$ → $K(k)$, ★argmax) ·
> C: warmth별 peak $k^*$ 이동 · D: $k^*(T)$ — 우리 DFlash(극단) vs steeper hazard(부드러운 중간).

## 슬라이드 17 — 매 라운드 루프 + warmth($T$) 추정

```python
block = DFlash.추측(문맥, k)          # 머리: 병렬 1회 (k는 a*=T/(1+T)로 결정)
tail  = Suffix.조회(문맥+block)        # 꼬리: CPU, 거의 공짜
accepted = target.검증_최장경로(문맥, block+tail)   # 한 번에 검증·채택
Suffix.기억에_추가(accepted)          # 데우기: 다음 요청부터 T 커짐 (복리)
```

- 머리 H = DFlash 블록(O(1)) · 꼬리 C = Suffix 트리(CPU, 채택분으로 데움).
- **$T$ 추정 두 방법**: (A) 검증 라벨(실제 채택 길이) EMA — 1~2 라운드 지연 / **(B) Suffix score — 검증 전
  즉시(빈도 기반), 지연 0.** 실측상 score가 ~3.7배 빨리 반응.

## 슬라이드 18 — 머리 신뢰도 $a_k$도 라이브로 (task 몰라도)

**$a_k$도 task마다 다른데(서빙 땐 task 모름), $T$처럼 추정한다. 가장 빠른 건 DFlash 자신의 confidence —
실측상 $a_k$를 거의 그대로 예측한다.**


- **DFlash confidence(softmax 확률) ≈ $a_k$**: 예측 생존 $\prod\text{conf}$ vs 측정 생존 $S_k$ **Pearson r=0.99**
  (얕은 conf↔hazard r=0.92). 작은 affine 보정 $a{\approx}0.69\,\text{conf}{+}0.29$. → **라운드 누적 없이 즉시.**


- **컨트롤러에 통합("warming 0")**: confidence로 oracle 매치(blocked 99.1% / 빠른전환 99.8%), no-estimation
  prior(74~81%) 압도. → **$T$(score) + $a_k$(confidence) 둘 다 라이브, 지연 0.**
